# Project Stack — Schedules Direct Update & Serve

## Overview
A Docker-based service that periodically fetches TV schedule data from [Schedules Direct](https://www.schedulesdirect.org/), converts it to XMLTV format via `tv_grab_zz_sdjson`, and serves it over HTTP for use with home media applications (Threadfin, Plex, Emby, Jellyfin, TVHeadend, etc.).

## Infrastructure

| Layer | Technology |
|-------|-----------|
| Container runtime | Docker / Docker Compose v3.8 |
| Base OS | Ubuntu (apt-based) |
| Web server | Nginx (serves XMLTV file on port 80 → mapped to host port 51969) |
| Scheduler | Cron (runs `/fetch_json.sh` daily at midnight via `/etc/cron.d/tvgrab-cron`) |
| CI/CD | GitHub Actions (`.github/workflows/docker-publish.yml`) — builds & pushes to Docker Hub on push to `main`/`master` |
| Image publish target | `mrorbitman/schedules-direct-update-and-serve:latest` (linux/amd64) |
| Data persistence | Named Docker volume `xmltv_data` mounted at `/var/www/html` |

## Languages & Tools

| Component | Language / Tool |
|-----------|----------------|
| Shell scripts | Bash (`start.sh`, `fetch_json.sh`) |
| Data conversion | `tv_grab_zz_sdjson` (Python-based XMLTV grabber from the `xmltv-util` package) |
| JSON handling | Python 3 (used inline in `fetch_json.sh` for escaping error messages) |
| HTTP serving | Nginx (static file serving from `/var/www/html`) |

## Key Files

| File | Purpose |
|------|---------|
| `Dockerfile` | Ubuntu base, installs `bash`, `xmltv-util`, `nginx`, `python3`, `cron` |
| `docker-compose.yaml` | Service definition, env vars, port mapping (51969→80), named volume |
| `start.sh` | Entry point — writes env vars, generates `tv_grab_zz_sdjson.conf`, starts cron, launches nginx in foreground |
| `fetch_json.sh` | Fetches data from Schedules Direct via `tv_grab_zz_sdjson`, validates output, writes status JSON |
| `tvgrab-cron` | Cron schedule: runs `fetch_json.sh` once per day at midnight, logs to stdout/stderr (container logs) |
| `.gitignore` | Ignores generated `tv_grab_zz_sdjson.conf` and `tvxml.xml` |

## Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `SD_USERNAME` | _(required)_ | Schedules Direct API username |
| `SD_PASSWORD` | _(required)_ | Schedules Direct API password |
| `SD_LINEUPS` | `USA-0000001-CUSTOM,USA-DITV505-X,USA-MI21464-X,USA-YOUTUBE-X` | Comma-separated lineup IDs |
| `SD_FETCH_DAYS` | `2` | Days of guide data to fetch per run |
| `TZ` | `UTC` | Timezone for the cron schedule |

## Runtime Flow

1. `start.sh` runs on container launch:
   - Dumps env vars to `/etc/environment` so cron can access them
   - Generates `/var/www/html/tv_grab_zz_sdjson.conf` from env vars
   - Starts cron daemon
   - Runs initial data fetch via `fetch_json.sh`
   - Starts Nginx in foreground (keeps container alive)

2. Cron triggers `fetch_json.sh` daily at midnight:
   - Calls `/usr/bin/tv_grab_zz_sdjson` with config file
   - Validates output is non-empty XML
   - Atomically replaces `tvxml.xml` on success
   - Writes `status.json` with last-success timestamp
   - On failure, writes `last_error.log` and `status.json` with error details

3. Nginx serves `tvxml.xml` at `http://<host>:51969/tvxml.xml`

## External Dependencies

- **Schedules Direct API** (`schedulesdirect.org`) — TV listing data source
- **`tv_grab_zz_sdjson`** — Perl/Python XMLTV grabber that talks to the SD JSON API
- **Docker Hub** — image registry for `mrorbitman/schedules-direct-update-and-serve`
